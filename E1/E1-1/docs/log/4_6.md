# 4.6 Ubuntu 컨테이너 실행 및 내부 진입 로그

## 1. 실습 목적

`ubuntu:24.04` 이미지로 대화형 컨테이너를 생성하고 컨테이너 내부의 Bash 터미널에 직접 진입하였다.

컨테이너 내부에서 기본 Linux 명령어를 실행하고 운영체제 정보를 확인하였다.

또한 `docker attach`와 `docker exec`를 사용하여 실행 중인 컨테이너에 접속하고 두 명령어의 차이를 확인하였다.

실습에 사용한 컨테이너 이름은 다음과 같다.

```text
ubuntu-shell
```

---

## 2. Ubuntu 컨테이너 생성 및 내부 진입

### 설명

`docker run` 명령어를 사용하여 `ubuntu:24.04` 이미지 기반의 새로운 컨테이너를 생성하고 실행하였다.

`-it` 옵션을 사용하여 사용자 입력이 가능한 대화형 터미널을 열고 컨테이너 내부에서 `bash`를 실행하였다.

### 코드

```bash
docker run -it --name ubuntu-shell ubuntu:24.04 bash
```

### 결과

```text
root@9391942d87da:/#
```

### 결과 설명

터미널의 명령 프롬프트가 다음과 같이 변경되었다.

```text
변경 전:
dldmswl@BOOK-5240G27HO6:~/codyssey/E-1-Project$

변경 후:
root@9391942d87da:/#
```

이는 WSL 터미널에서 Ubuntu 컨테이너 내부의 Bash 터미널로 진입했다는 뜻이다.

```text
root          컨테이너 내부 사용자
9391942d87da  컨테이너 ID
/             컨테이너 내부의 현재 경로
```

---

## 3. 컨테이너 내부 현재 위치 확인

### 설명

컨테이너 내부에서 `pwd` 명령어를 사용하여 현재 작업 위치를 확인하였다.

### 코드

```bash
pwd
```

### 결과

```text
/
```

### 결과 설명

현재 작업 위치가 Linux 파일 시스템의 최상위 경로인 `/`로 표시되었다.

컨테이너를 실행할 때 별도의 작업 디렉토리를 지정하지 않았기 때문에 루트 디렉토리에서 Bash가 시작되었다.

---

## 4. 컨테이너 내부 파일 목록 확인

### 설명

`ls` 명령어를 사용하여 컨테이너 내부 루트 디렉토리의 파일과 디렉토리 목록을 확인하였다.

### 코드

```bash
ls
```

### 결과

```text
bin  boot  dev  etc  home  lib  lib64  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
```

### 결과 설명

Ubuntu 컨테이너 내부에 Linux 시스템을 구성하는 기본 디렉토리가 존재하는 것을 확인하였다.

| 디렉토리 | 의미 |
|---|---|
| `/bin` | 기본 명령어 파일 |
| `/etc` | 시스템 설정 파일 |
| `/home` | 일반 사용자 홈 디렉토리 |
| `/root` | root 사용자 홈 디렉토리 |
| `/tmp` | 임시 파일 저장 디렉토리 |
| `/usr` | 프로그램과 라이브러리 |
| `/var` | 로그 등 변경되는 데이터 |

## 5. 컨테이너 내부 문자열 출력

### 설명

`echo` 명령어를 사용하여 컨테이너 내부에서 명령어가 정상적으로 실행되는지 확인하였다.

### 코드

```bash
echo "Hello Docker"
```

### 결과

```text
Hello Docker
```

### 결과 설명

입력한 문자열이 정상적으로 출력되었다.

이를 통해 Ubuntu 컨테이너 내부의 Bash가 정상적으로 작동하고 있음을 확인하였다.

`/etc/os-release` 파일을 확인하여 컨테이너 내부에서 사용되는 Linux 배포판과 버전을 확인하였다.

### 코드

```bash
cat /etc/os-release
```

### 결과

```text

NAME="Ubuntu"

UBUNTU_CODENAME=noble
LOGO=ubuntu-logo
```

### 결과 설명

컨테이너 내부의 운영체제 정보는 다음과 같다.

```text
운영체제: Ubuntu
버전: 24.04.4 LTS
코드명: Noble Numbat
```

`ubuntu:24.04` 이미지 기반의 컨테이너가 정상적으로 생성된 것을 확인하였다.

## 7. 컨테이너 내부 Bash 종료

### 설명

컨테이너 내부에서 `exit` 명령어를 사용하여 Bash를 종료하였다.

### 코드

```bash
exit
```

### 결과

```text
exit
```

### 결과 설명

`docker run`으로 실행한 Bash는 이 컨테이너의 주 프로세스이다.

따라서 Bash에서 `exit`를 실행하자 주 프로세스가 종료되면서 컨테이너도 함께 중지되었다.

---

## 8. 컨테이너 종료 상태 확인

### 설명

`docker ps -a` 명령어를 사용하여 `ubuntu-shell` 컨테이너의 종료 상태를 확인하였다.

### 코드

```bash
docker ps -a
```

### 결과

```text
CONTAINER ID   IMAGE          COMMAND                  CREATED              STATUS                        PORTS     NAMES
9391942d87da   ubuntu:24.04   "bash"                   About a minute ago   Exited (0) 13 seconds ago               ubuntu-shell
65d11b3ee6a6   hello-world    "/hello"                 18 minutes ago       Exited (0) 18 minutes ago               vigorous_brahmagupta
a1aa86e1ecfd   ubuntu:24.04   "sh -c 'while true; …"   39 minutes ago       Exited (137) 30 minutes ago             ubuntu-practice
```

### 결과 설명

`ubuntu-shell` 컨테이너의 상태가 다음과 같이 표시되었다.

```text
Exited (0)
```

종료 코드 `0`은 컨테이너 내부의 Bash가 오류 없이 정상적으로 종료되었다는 뜻이다.

## 9. 중지된 컨테이너 다시 시작

### 설명

`docker start` 명령어를 사용하여 기존의 `ubuntu-shell` 컨테이너를 다시 실행하였다.

`docker start`는 새로운 컨테이너를 생성하지 않고 이미 만들어져 있는 중지된 컨테이너를 다시 실행한다.

### 코드

```bash
docker start ubuntu-shell
```

### 결과

```text
ubuntu-shell
```

### 결과 설명

기존의 `ubuntu-shell` 컨테이너가 정상적으로 다시 시작되었다.

## 10. 재실행 상태 확인

### 설명

`docker ps` 명령어를 사용하여 다시 시작한 컨테이너가 실행 중인지 확인하였다.

### 코드

```bash
docker ps
```

### 결과

```text

```

### 결과 설명

`STATUS` 항목이 `Up 11 seconds`로 표시되어 컨테이너가 정상적으로 실행 중인 것을 확인하였다.

---

## 11. docker attach를 사용한 접속

### 설명

`docker attach` 명령어를 사용하여 실행 중인 컨테이너의 기존 주 터미널에 연결하였다.

### 코드

```bash
docker attach ubuntu-shell
```

컨테이너 내부에서 다음 명령어를 실행하였다.

```bash
echo "Attached to container"
```

### 결과

```text
root@9391942d87da:/# echo "Attached to container"
Attached to container
```

### 결과 설명

`docker attach`를 사용하여 컨테이너에서 기존에 실행 중인 Bash 터미널에 직접 연결하였다.

첫 번째 실습에서는 attach 상태에서 다음 명령어를 실행하였다.

```bash
exit
```

그 결과 컨테이너의 주 프로세스인 Bash가 종료되면서 컨테이너도 중지되었다.

---

## 12. 사용자 지정 분리 키로 attach 연결 종료

### 설명

컨테이너를 중지하지 않고 attach 연결만 종료하기 위해 Docker의 분리 키를 사용하였다.

VS Code 터미널에서 기본 분리 키인 `Ctrl + P`, `Ctrl + Q`가 정상적으로 입력되지 않아 `--detach-keys` 옵션을 사용하여 분리 키를 소문자 `x`로 지정하였다.

### 코드

```bash
docker start ubuntu-shell
docker attach --detach-keys="x" ubuntu-shell
```

컨테이너 내부에서 다음 명령어를 실행하였다.

```bash
echo "Attached to container"
```

그다음 소문자 `x`를 입력하여 attach 연결만 종료하였다.

### 결과

```text
root@9391942d87da:/# echo "Attached to container"
Attached to container
root@9391942d87da:/# read escape sequence
```

### 결과 설명

`read escape sequence`가 표시된 뒤 WSL 터미널로 돌아왔다.

`exit`를 사용하지 않고 분리 키를 사용했기 때문에 컨테이너의 주 프로세스는 종료되지 않았다.

---

## 13. attach 분리 후 실행 상태 확인

### 설명

attach 연결을 종료한 이후에도 컨테이너가 계속 실행 중인지 확인하였다.

### 코드

```bash
docker ps
```

### 결과

```text
CONTAINER ID   IMAGE          COMMAND   CREATED         STATUS          PORTS     NAMES
9391942d87da   ubuntu:24.04   "bash"    9 minutes ago   Up 39 seconds             ubuntu-shell
```

### 결과 설명

`ubuntu-shell`의 상태가 `Up 39 seconds`로 표시되었다.

따라서 사용자 지정 분리 키를 사용하면 컨테이너를 중지하지 않고 attach 연결만 종료할 수 있음을 확인하였다.

## 14. docker exec를 사용한 내부 진입

### 설명

`docker exec` 명령어를 사용하여 실행 중인 `ubuntu-shell` 컨테이너 내부에서 새로운 Bash 프로세스를 실행하였다.

`docker attach`는 기존 주 터미널에 연결하지만, `docker exec`는 실행 중인 컨테이너에 새로운 명령어나 셸을 추가로 실행한다.

### 코드

```bash
docker exec -it ubuntu-shell bash
```

컨테이너 내부에서 다음 명령어를 실행하였다.

```bash
echo "Entered with docker exec"
pwd
exit
```

### 결과

```text
root@9391942d87da:/# echo "Entered with docker exec"
Entered with docker exec
root@9391942d87da:/# pwd
/
root@9391942d87da:/# exit
exit
```

### 결과 설명

`docker exec`를 사용하여 컨테이너 내부에 새로운 Bash를 정상적으로 실행하였다.

현재 위치는 다음과 같이 표시되었다.

```text
/
```

`exit`를 실행하자 `docker exec`로 추가한 Bash만 종료되고 WSL 터미널로 돌아왔다.

---

## 15. exec 종료 후 컨테이너 상태 확인

### 설명

`docker exec`로 실행한 Bash를 종료한 뒤에도 원래 컨테이너가 실행 중인지 확인하였다.

### 코드

```bash
docker ps
```

### 결과

```text
CONTAINER ID   IMAGE          COMMAND   CREATED          STATUS         PORTS     NAMES
9391942d87da   ubuntu:24.04   "bash"    12 minutes ago   Up 4 minutes             ubuntu-shell
```

### 결과 설명

`docker exec`로 실행한 Bash에서 `exit`를 입력했지만 `ubuntu-shell` 컨테이너는 계속 `Up` 상태로 실행되고 있었다.

이를 통해 `docker exec`로 실행한 추가 프로세스의 종료는 컨테이너의 기존 주 프로세스에 영향을 주지 않는다는 것을 확인하였다.

---

## 16. 중지된 컨테이너에서 exec 실행

### 설명

컨테이너를 중지한 뒤 `docker exec` 명령어를 실행하여 중지 상태에서의 동작을 확인하였다.

### 코드

```bash
docker exec -it ubuntu-shell bash
```

### 결과

```text
Error response from daemon: container 9391942d87da40bfee8c05e183542c59b553ac6cda393a8d5ae030bfb447d678 is not running
```

### 결과 설명

`docker exec`는 실행 중인 컨테이너에서만 사용할 수 있다.

따라서 중지된 `ubuntu-shell` 컨테이너에서 실행했을 때 다음 오류가 발생하였다.

```text
is not running
```

오류를 해결하기 위해 컨테이너를 먼저 다시 시작하였다.

### 해결 코드

```bash
docker start ubuntu-shell
docker ps
docker exec -it ubuntu-shell bash
```

### 해결 결과

```text
ubuntu-shell

CONTAINER ID   IMAGE          COMMAND   CREATED          STATUS         PORTS     NAMES
9391942d87da   ubuntu:24.04   "bash"    16 minutes ago   Up 6 seconds             ubuntu-shell
```

컨테이너 내부 진입 후 다음 명령어를 실행하였다.

```bash
echo "Entered with docker exec"
pwd
```

### 실행 결과

```text
Entered with docker exec
/
```

### 해결 결과 설명

중지된 컨테이너를 `docker start`로 다시 실행한 뒤 `docker exec`를 사용하자 정상적으로 컨테이너 내부에 진입할 수 있었다.

## 18. 최종 컨테이너 상태 확인

### 설명

`docker ps -a` 명령어를 사용하여 실습에 사용한 컨테이너의 최종 상태를 확인하였다.

### 코드

```bash
docker ps -a
```

### 결과

```text
CONTAINER ID   IMAGE          COMMAND                  CREATED          STATUS                        PORTS     NAMES
9391942d87da   ubuntu:24.04   "bash"                   17 minutes ago   Exited (137) 2 seconds ago              ubuntu-shell
65d11b3ee6a6   hello-world    "/hello"                 34 minutes ago   Exited (0) 34 minutes ago               vigorous_brahmagupta
a1aa86e1ecfd   ubuntu:24.04   "sh -c 'while true; …"   55 minutes ago   Exited (137) 46 minutes ago             ubuntu-practice
```

### 결과 설명

따라서 실습 종료 후 컨테이너가 중지된 것을 확인하였다.

컨테이너는 삭제하지 않았기 때문에 필요할 때 다음 명령어로 다시 실행할 수 있다.

```bash

```

## 19. run, start, attach, exec 차이

| 명령어 | 기능 | 새 컨테이너 생성 | 주요 특징 |
|---|---|---:|---|
| `docker run` | 이미지로 컨테이너를 생성하고 실행 | O | 처음 컨테이너를 만들 때 사용 |
| `docker start` | 중지된 기존 컨테이너를 다시 실행 | X | 기존 컨테이너를 재사용 |
| `docker attach` | 컨테이너의 기존 주 터미널에 연결 | X | `exit`하면 주 프로세스가 종료될 수 있음 |
| `docker exec` | 실행 중인 컨테이너에 새 명령어나 셸 실행 | X | 추가 셸을 종료해도 원래 컨테이너는 계속 실행 |
