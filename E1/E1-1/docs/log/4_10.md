# 4.10 Docker 볼륨 영속성 로그

## 1. 실습 목적

Docker 볼륨을 생성하고 컨테이너 내부의 디렉토리에 연결하였다.

첫 번째 컨테이너에서 볼륨 내부에 파일을 생성한 뒤 해당 컨테이너를 삭제하였다.

이후 새로운 컨테이너에 같은 볼륨을 연결하여 기존 파일이 유지되는지 확인함으로써 Docker 볼륨의 데이터 영속성을 검증하였다.

실습에 사용한 주요 이름은 다음과 같다.

```text
Docker 볼륨: e1-data-volume
첫 번째 컨테이너: volume-test-1
두 번째 컨테이너: volume-test-2
볼륨 연결 경로: /data
저장 파일: /data/persistence.txt
```

---

## 2. Docker 볼륨 생성

### 설명

`docker volume create` 명령어를 사용하여 `e1-data-volume`이라는 Docker 볼륨을 생성하였다.

Docker 볼륨은 컨테이너의 파일 시스템과 분리되어 관리되는 데이터 저장 공간이다.

### 코드

```bash
docker volume create e1-data-volume
```

### 결과

```text
e1-data-volume
```

### 결과 설명

명령어 실행 결과로 생성한 볼륨 이름이 출력되었다.

```text
e1-data-volume
```

이를 통해 Docker 볼륨이 정상적으로 생성되었음을 확인하였다.

---

## 3. Docker 볼륨 목록 확인

### 설명

`docker volume ls` 명령어를 사용하여 현재 Docker 환경에 존재하는 볼륨 목록을 확인하였다.

### 코드

```bash
docker volume ls
```

### 결과

```text
DRIVER    VOLUME NAME
local     e1-data-volume
```

### 결과 설명

볼륨 목록에서 `e1-data-volume`이 확인되었다.

```text
드라이버: local
볼륨 이름: e1-data-volume
```

`local` 드라이버는 현재 Docker 환경의 로컬 저장 공간에서 볼륨을 관리한다는 뜻이다.

---

## 4. 첫 번째 컨테이너에 볼륨 연결

### 설명

`ubuntu:24.04` 이미지로 `volume-test-1` 컨테이너를 생성하였다.

`-v` 옵션을 사용하여 `e1-data-volume` 볼륨을 컨테이너 내부의 `/data` 디렉토리에 연결하였다.

컨테이너 내부에서 `persistence.txt` 파일을 생성하고 문자열을 저장한 뒤, 저장된 내용을 바로 확인하였다.

### 코드

```bash
docker run --name volume-test-1 \
  -v e1-data-volume:/data \
  ubuntu:24.04 \
  bash -c 'echo "Docker volume data persists" > /data/persistence.txt && cat /data/persistence.txt'
```

### 결과

```text
Docker volume data persists
```

### 결과 설명

컨테이너 내부의 다음 파일에 문자열이 저장되었다.

```text
/data/persistence.txt
```

파일에 저장한 내용은 다음과 같다.

```text
Docker volume data persists
```

`/data` 디렉토리는 `e1-data-volume`과 연결되어 있으므로 파일은 컨테이너 자체가 아니라 Docker 볼륨에 저장되었다.

---

## 5. 첫 번째 컨테이너 종료 상태 확인

### 설명

첫 번째 컨테이너의 명령어 실행이 끝난 후 `docker ps -a` 명령어를 사용하여 컨테이너의 상태를 확인하였다.

### 코드

```bash
docker ps -a
```

### 결과

```text
CONTAINER ID   IMAGE          COMMAND                   CREATED          STATUS                      PORTS   NAMES
984f6e0fdc64   ubuntu:24.04   "bash -c 'echo \"Dock…"   11 seconds ago   Exited (0) 11 seconds ago           volume-test-1
```

### 결과 설명

`volume-test-1` 컨테이너가 다음 상태로 표시되었다.

```text
Exited (0)
```

종료 코드 `0`은 컨테이너 내부의 명령어가 오류 없이 정상적으로 완료되었다는 뜻이다.

파일 생성과 출력 작업이 끝났기 때문에 컨테이너가 자동으로 종료되었다.

---

## 6. 첫 번째 컨테이너 삭제

### 설명

데이터가 컨테이너 자체가 아니라 Docker 볼륨에 저장되는지 확인하기 위해 첫 번째 컨테이너를 삭제하였다.

볼륨은 삭제하지 않고 컨테이너만 삭제하였다.

### 코드

```bash
docker rm volume-test-1
```

### 결과

```text
volume-test-1
```

### 결과 설명

삭제된 컨테이너 이름이 출력되었다.

```text
volume-test-1
```

따라서 첫 번째 컨테이너가 정상적으로 삭제되었음을 확인하였다.

---

### 코드

```bash
docker ps -a
```

따라서 첫 번째 컨테이너가 정상적으로 삭제되었다.

---

## 8. 컨테이너 삭제 후 볼륨 확인

### 설명

첫 번째 컨테이너를 삭제한 이후에도 Docker 볼륨이 유지되는지 확인하였다.

### 코드

```bash
docker volume ls
```

### 결과

```text
DRIVER    VOLUME NAME
local     e1-data-volume
```

### 결과 설명

`volume-test-1` 컨테이너를 삭제했지만 `e1-data-volume`은 볼륨 목록에 그대로 남아 있었다.

이를 통해 Docker 볼륨은 컨테이너의 생명주기와 별도로 관리된다는 것을 확인하였다.

```text
컨테이너: 삭제됨
볼륨: 유지됨
```

---

## 9. 새로운 컨테이너에서 기존 데이터 확인

### 설명

새로운 `volume-test-2` 컨테이너에 기존의 `e1-data-volume`을 다시 연결하였다.

첫 번째 컨테이너에서 생성한 `/data/persistence.txt` 파일을 읽어 데이터가 유지되었는지 확인하였다.

`--rm` 옵션을 사용하여 명령어 실행이 끝난 뒤 두 번째 컨테이너가 자동으로 삭제되도록 설정하였다.

### 코드

```bash
docker run --rm --name volume-test-2 \
  -v e1-data-volume:/data \
  ubuntu:24.04 \
  cat /data/persistence.txt
```

### 결과

```text
Docker volume data persists
```

### 결과 설명

새로 생성한 `volume-test-2` 컨테이너에서 첫 번째 컨테이너가 저장했던 파일 내용을 정상적으로 읽었다.

```text
Docker volume data persists
```

첫 번째 컨테이너는 이미 삭제된 상태였지만 데이터가 그대로 출력되었다.

따라서 데이터가 컨테이너 내부 파일 시스템이 아니라 `e1-data-volume`에 저장되어 유지된 것을 확인하였다.

---

## 10. Docker 볼륨 영속성 검증 과정

```text
e1-data-volume 생성
        ↓
volume-test-1에 /data로 연결
        ↓
/data/persistence.txt 파일 생성
        ↓
volume-test-1 종료
        ↓
volume-test-1 삭제
        ↓
e1-data-volume은 그대로 유지
        ↓
volume-test-2에 같은 볼륨 연결
        ↓
기존 persistence.txt 파일 읽기 성공
        ↓
Docker 볼륨 데이터 영속성 확인
```

---

## 11. 컨테이너 저장 공간과 Docker 볼륨 차이

| 구분 | 컨테이너 내부 저장 공간 | Docker 볼륨 |
|---|---|---|
| 관리 대상 | 특정 컨테이너 | Docker 엔진 |
| 컨테이너 삭제 시 | 데이터가 함께 사라질 수 있음 | 데이터가 유지됨 |
| 다른 컨테이너 연결 | 직접 사용하기 어려움 | 같은 볼륨을 연결하여 사용 가능 |
| 주요 용도 | 임시 실행 데이터 | 데이터베이스, 업로드 파일, 설정 등 지속 데이터 |

---

## 12. 주요 명령어 정리

| 명령어 | 기능 |
|---|---|
| `docker volume create e1-data-volume` | 새로운 Docker 볼륨 생성 |
| `docker volume ls` | Docker 볼륨 목록 확인 |
| `-v e1-data-volume:/data` | 볼륨을 컨테이너의 `/data`에 연결 |
| `docker rm volume-test-1` | 첫 번째 컨테이너 삭제 |
| `docker run --rm` | 컨테이너 종료 후 자동 삭제 |
| `cat /data/persistence.txt` | 볼륨에 저장된 파일 내용 확인 |
